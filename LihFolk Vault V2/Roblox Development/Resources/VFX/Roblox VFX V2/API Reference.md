## 1. `VFXKit` (harvest route)

Source: `references/VFXKit.lua`, generated by `scripts/emit_luau.py`. A ModuleScript holding your curated recipes in `VFXKit.Recipes` (empty in the repo).

### `VFXKit.build(recipeName, targetPart, opts?) -> handle`

| Parameter | Type | Notes |
|---|---|---|
| `recipeName` | string | A key in `VFXKit.Recipes` (the name you gave it in `curate.py`). Asserts if missing |
| `targetPart` | BasePart | **Must be a BasePart** (asserted). An Attachment under a Model or Folder has no world position, so the effect would build at the world origin |
| `opts.scale` | number | Scales Size, Speed, Acceleration, light Range, layer offsets and burst counts |
| `opts.tint` | Color3 | Replaces hue but **keeps the luminance ramp** (bright core to dark tail) |
| `opts.lifetime_mul` | number | Multiplies `Lifetime` |
| `opts.rate_mul` | number | Multiplies `Rate` (continuous layers) |
| `opts.offset` | Vector3 | Local offset of every layer's Attachment from the part |
| `opts.suffix` | string | Makes an independent second instance. Without it, building the same name again **replaces** the first |

What it builds: one Attachment per layer under `targetPart` (tagged with the `VFXTag` attribute), each holding a ParticleEmitter, Beam, Trail or PointLight. Burst layers get `Rate = 0`. Beam and Trail endpoints are wired from the recipe's `endpoints`.

| Handle member | Does |
|---|---|
| `handle.emit(mult?)` | `:Emit(count × mult)` on every **burst** layer; pulses **pulse** lights (peak × mult, quadratic decay over `PulseSeconds`) |
| `handle.setEnabled(on)` | Turns **continuous** emitters, **constant** lights and non-burst Beams/Trails on or off |
| `handle.destroy()` | Destroys every Attachment with this effect's tag on the part |
| `handle.emitters`, `handle.lights`, `handle.ribbons`, `handle.tag` | The created instances and the tag string |

Layer emit modes (`emit.mode` in a recipe): `burst` (one-shot), `continuous` (streams at `Rate`), `pulse` (light flash), `constant` (light stays on).

## 2. Studio kits (author route)

Generated by `node sim/studio_kit.js <effect.json> <out_dir>`, which writes `<name>.luau` (a ModuleScript `M`) and `<name>.assets.json`. The split exists because a game script cannot set `MeshPart.MeshId` or `SurfaceAppearance.ColorMap`. Edit mode builds a template once; runtime only clones it.

| Member | Where it runs | Does |
|---|---|---|
| `M.NAME`, `M.DURATION` | anywhere | Effect name and length in seconds |
| `M.NEEDS` | anywhere | `{textures = {"sim:..."}, meshes = {"sim:..."}}`: every asset id the kit needs uploaded |
| `M.PROP_FAILS` | after building | Table of `Class.Prop` writes that failed (each warned once) |
| `M.buildTemplate(assets, parent) -> Folder` | **Edit mode**: command bar or plugin | Builds every instance once, meshes through `AssetService:CreateMeshPartAsync`, and parents a Folder named `M.NAME` under `parent`. `assets = {textures = {["sim:x"] = "rbxassetid://N"}, meshes = {["sim:y"] = "rbxassetid://MESH_ID"}}`. Meshes need the **mesh** id, not the model id |
| `M.preload(template) -> number` | runtime (yields) | `ContentProvider:PreloadAsync` on the template plus every map and mesh id; returns the count that failed. Call it at join |
| `M.spawn(origin, template, opts?) -> h` | runtime, **LocalScript** | Clones the template into `workspace`, moves every part by `origin` (a CFrame), and moves grade/bloom effects into Lighting. `opts.screen = false` drops the screen-space pieces (Lighting effects, `IF*` impact-frame rig, camera, overlays); `opts.game = true` leaves the caster's root to the game's physics |
| `M.play(h)` | runtime | Plays the timeline with `task.delay` (does not yield), then destroys `h.folder` and the Lighting effects `DURATION + 1` s later |
| `h` fields | | `folder`, `byPath`, `origin`, `lighting`, `screen`, `game`. Set `h.caster` (a character Model) before `play` to drive the caster animation and caster Highlights, and `h.target` for target Highlights and `hideTarget` |
| `M.animate(h, character)` | runtime | Drives the caster rig from the effect's `rig` block (called by `play` when `h.caster` is set) |
| `M.applyStage(h)` | runtime | Applies the effect's night/fog stage to Lighting and stores `h.restoreStage` |
| `M.hideTarget(h, on)` | runtime | Hides or shows `h.target` with `LocalTransparencyModifier` |
| `M.ghost(h, ...)`, `M.poseAt`, `M.rigCFs`, `M.STAGE`, `M.ACTORS`, `M.FOLLOW`, `M.RIG`, `M.TARGET_AT` | internal | Afterimages and rig helpers used by `play`. `M.TARGET_AT` and `M.RIG` exist only when the effect defines a target or rig |

> [!warning] Camera takeover
> If the effect defines a camera and `h.screen ~= false`, `M.play` sets `workspace.CurrentCamera.CameraType` to `Scriptable` and **never sets it back**. Use `Kit.spawn(origin, template, {screen = false})` for ordinary gameplay moves, or restore the camera yourself (see [[Roblox VFX V2/Examples|Examples]]). Found by reading the generated kits on 2026-11-19.

## 3. `HitSystem` (reference module)

Source: `references/HitSystem.luau` (813 lines, `--!strict`). It is written for the showcase: **client-side**, on an R6 target the director spawns locally. It uses the collision groups `ShowcaseFX` and `ShowcaseTarget`.

| Function | Does |
|---|---|
| `HitSystem.spawnTarget(at: CFrame, name: string?) -> Model` | Spawns an R6 sparring target with an overhead health bar |
| `HitSystem.Hit(target, ev: HitEvent)` | Applies a hit. `HitEvent = {damage, knock: Vector3 (world displacement reached after time), time, reaction = "flinch" \| "knockback" \| "launch" \| "ragdoll", stun, ultimate, hitstop}`. Health floors at 1 (the showcase never kills) |
| `HitSystem.recover(target)` | Lets a downed body get up |
| `HitSystem.isStanding(target) -> boolean` | True when the body is standing |
| `HitSystem.reset(target, at: CFrame, refill?)` | Full health, joints back, standing at `at`, undoes whatever a kit did to the target |
| `HitSystem.placeRoot(model, at: CFrame)` | Places a rig by its root and grounds it by its feet |
| `HitSystem.ensureGroups() -> boolean` | Creates the two collision groups |
| `HitSystem.FX_GROUP`, `HitSystem.TARGET_GROUP`, `HitSystem.MAX_HEALTH` | `"ShowcaseFX"`, `"ShowcaseTarget"`, `100` |

`references/CharacterVFX.server.lua` is a worked server script. It builds `VFXKit` recipes (an aura and a landing impact) on every character, scales the landing burst with fall speed, and has you set `AURA_RECIPE` and `IMPACT_RECIPE` to your own recipe names.

## 4. Command-line tools (run from the skill folder)

| Command | Purpose |
|---|---|
| `python sim/serve.py` | Workbench server for the browser sim (`POST /save?name=x.png` saves strips to `sim/out/`) |
| `node sim/studio_kit.js <effect.json> <out_dir>` | Effect definition to Studio kit + assets list |
| `python scripts/critic_gate.py <effect.json> [--metrics m.json]` | Design-rule gate for an effect definition |
| `python sim/tools/sa_parent_check.py` | No SurfaceAppearance off a MeshPart |
| `node sim/tools/phys_audit.js [prefix ...]` | Hit/body physics audit for effects with `hit` events |
| `lune run sim/tools/lune/compile_check.luau <kit>` / `build_check.luau <kit>` | Compile check and a `buildTemplate` dry run against Roblox reflection |
| `python sim/tex/lib/find_tex.py <words>` | Search the texture library (`sim:lib/...` ids) |
| `python scripts/payload.py harvest --root PATH --out work/h.lua` | Build a harvest payload for Studio |
| `python scripts/recipe_server.py [--port 48752] [--out DIR]` | Receives harvests; serves `work/*.lua` |
| `python scripts/classify_lib.py --lib DIR [--stage ...] [--sheet ring]` | Builds `index.json` and audit sheets |
| `python scripts/find_vfx.py --lib DIR <words> [--layered] [--portable] [--tag T]` | Searches your library |
| `python scripts/curate.py --lib LIB --out DIR --pick "Name=Stem\|layers*mul@burst"` | Copies the recipes a game uses, renamed by role |
| `python scripts/assemble_kit.py --lib LIB --spec spec.json --out DIR` | Builds a kit from many recipes with tint/scale baked in (`--self-test`) |
| `python scripts/emit_luau.py --lib DIR [--compact] [--data-dir D] out.lua` | Writes the `VFXKit` ModuleScript |
| `python scripts/verify_vfx.py --lib DIR [--quiet]` / `--self-test` | Recipe defect checks. `--lib` is required even for one file |
| `python scripts/compose.py comp.json --lib LIB --freeze 0.45 --out work/s.lua` | Edit-mode payload for a composition at one phase |
| `python scripts/emit_scenes.py --lib LIB --comps DIR --out-dir work` | `VFXScenes` module + `VFXDemo` LocalScript |

## 5. Recipe format (summary)

```jsonc
{
  "name": "MyImpact",
  "duration": 1.9,
  "texture_portable": true,
  "texture_refs": ["rbxasset://textures/particles/fire_main.dds"],
  "layers": [{
    "name": "Fire", "class": "ParticleEmitter",   // or Beam, Trail, PointLight
    "offset": [0, 0, 0],
    "emit": {"mode": "burst", "count": 16},
    "props": { /* all 31 ParticleEmitter properties, typed */ }
  }]
}
```

Typed values follow Rojo's convention: `{"NumberSequence": [[t, v, env]]}`, `{"ColorSequence": [[t, [r, g, b]]]}`, `{"NumberRange": [min, max]}`, `{"Vector3": [...]}`, `{"Vector2": [...]}`, `{"Color3": [...]}`, `{"Enum": "NormalId.Top"}`. `verify_vfx.py` fails any ParticleEmitter layer missing one of the 31 properties, and any PointLight missing `Brightness`, `Color`, `Enabled`, `Range` or `Shadows`. A full passing recipe is in [[Roblox VFX V2/Examples|Examples]].

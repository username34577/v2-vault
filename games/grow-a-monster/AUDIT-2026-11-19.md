# Grow a Monster — Audit (2026-11-19)

Back to [[README]] · Research: [[New Roblox Hits - Design Lessons (Nov 2026)]] · Plan: [[DESIGN-v0.4-overhaul]]

Inspected: all 19 Luau files in `src/`, the running game in Studio (several play sessions, screenshots at Size 1 and Size 30K), `DESIGN-v0.3.md`, the vault skills list.

## Verdict

The **engineering is solid; the game is not.** Saving, security and the look of the island are worth keeping. The monster and the core loop are the problem, and both are structural, not polish.

## Keep (works, has a purpose)

| System | Why keep it |
|---|---|
| `Data.luau` session-locked saving, schema migration | Hard to get right, already correct. New fields are added through `newData()` + `migrate()` |
| Server authority: rate-limited remotes, server-owned prices/growth/coins, range checks | Required for any economy. Pattern carries straight over to new mechanics |
| `Config.luau` as the single tuning file | Fast iteration |
| Island, hub, plots, lighting, cloud sea (`World`, `Decor`) | Reads well in screenshots; the right cozy-bright style |
| UI kit (`UI.luau`), HUD layout, responsive scale, toasts | Mobile-safe, consistent |
| Feel: crumbs, "+X", coin fly, bump (`Feel.luau`) | Good juice, reusable for any reward |
| `Fx` server→client cue remote | Cheap way to sync effects without trusting clients |

## Biggest problems (ranked)

1. **There is one verb, and it can't fail.** The whole game is "press THROW". Every throw hits (the server applies the hit after a fixed delay). No aim, no movement, no risk, no decision. Players never need to leave the spot they spawn on.
2. **Nothing to explore.** The island is a ring of identical plots and a hub. No place is worth walking to; nothing is hidden or locked.
3. **The monster is a static blob of ~20 primitive parts.** No legs that walk, no neck, no rig, no real silhouette. It is animated by moving parts each frame (squash, hop, blink), so it can never walk, run, or interact with the world. At Size 30K it is ~60 studs and spills out of its plot.
4. **Progression is one straight line.** 6 foods, each "buy the next one". Passive income means the best strategy is to stand still (an idle game wearing a clicker's clothes).
5. **The game is silent.** Every `Config.Sounds` slot is empty, so no sound plays at all.
6. **No social play.** Other players are only names on a board.
7. **First 30 seconds** (after the 2026-11-19 fixes): you see your monster and a "press F" pill. That's an instruction, not an objective. Nothing pulls you anywhere.

## Smaller issues seen in Studio

- Shop grid opens scrolled down, cutting off the top row (seen in Studio while a player had it open).
- Warning `rbxassetid://203785492 failed: Asset type does not match` — not in our code; comes from the place or a plugin.
- v0.3 step 1 fixes are in (monster size at spawn, stage, crate, gate arch, owner sign, plot decor tiers, +1/sec minimum income, camera framing).

## What this means

Adding passes, mutations and pets on top (the v0.3 plan) would multiply numbers on a loop that isn't fun yet. Fix the loop and the monster first, as one playable slice, then layer the systems back on.
